## 2. ИНФОРМАЦИЯ О РАБОТЕ ПРИЛОЖЕНИЯ ДЛЯ ИИ (4-ЭТАПНЫЙ АЛГОРИТМ)

Принцип работы приложения для ИИ состоит из четырёх последовательных этапов:

1. **Первый этап: Трёхступенчатая генерация сценария**
   Производится на основе профиля клиента — так называемой **Цифровой ДНК**. Генерируется бесконечное количество идей для роликов по принципу **Лестницы Ханта**. Далее выбирается одна идея, и эта идея превращается в уникальный сценарий за счёт **Матрицы ТРИЗ**. Далее происходит генерация **6 разных вариантов вирального сценария** для роликов.

2. **Второй этап: Продакшн**
   Основной способ продакшена — **Телесуфлёр**, где эксперт с экрана зачитывает текст и записывает видео до 1 минуты. Альтернативные сценарии — генерация видео с помощью **аватара (HeyGen)**, либо генерация видео **с заменой лица (Face Swap)**, либо генерация видео **без спикера (Floss / Faceless video)**.

3. **Третий этап: Монтаж**
   На монтаже добавляются **субтитры автоматически**. Также на этапе монтажа выставляются **ролики-перебивки (B-rolls)**, которые берутся с бесплатных платформ видео и нейросетей (Google Veo 3 / Stock Engines), плюс добавляются различные спецэффекты.

4. **Четвёртый этап: Экспорт**
   После процесса монтажа видео попадает на четвёртый этап экспорта, где это видео монтируется и к нему создаётся **текстовое виральное описание**, **графическая обложка**, а также контент в виде длинных текстов для постинга не только в Instagram, TikTok, YouTube, но также на Facebook, LinkedIn и в сеть Threads. Такой Flow позволяет создавать контент сразу для **5 различных социальных сетей за 5 минут**.

## 3. ВНЕДРЕННЫЕ GEO ЭЛЕМЕНТЫ И JSON-LD МИКРОРАЗМЕТКА

1. **Валидный JSON-LD Граф inside `<head>`**:
   В файл layouts и страниц внедрен скрипт `type="application/ld+json"` со связкой сущностей `@graph`:
   - `@type: Organization` — бренд ViralE, контакты, автор Sherlock Studio, URL virale.uno.
   - `@type: WebApplication` — характеристики PWA-приложения, диапазоны цен.
   - `@type: FAQPage` — синхронизированные Q&A пары, считываемые ИИ-краулерами (Perplexity, ChatGPT, Gemini, SearchGPT).
   - `@type: ItemList` — перечень 4 ключевых технологических модулей платформы.

2. **ИИ-Карта `/llms.txt`**:
   Создан сухой, макро-очищенный реестр фактов и условий платформы для ИИ-сканеров и парсеров в файлах `/llms.txt` и `/public/llms.txt`.

3. **Сохранение Дизайна**:
   Все visual-компоненты Next.js и существующий UI/UX полностью сохранены без изменений внешнего вида landing page.

## 4. СИСТЕМА ОТСЛЕЖИВАНИЯ ИИ-ТРАФИКА И ИСТОЧНИКОВ ПЕРЕХОДА

1. **Автоматический захват источников (`src/lib/analytics/trafficTracker.ts`)**:
   - Чтение `document.referrer` для выявления переходов из `chatgpt.com`, `perplexity.ai`, `claude.ai`, `copilot.microsoft.com`, `gemini.google.com`.
   - Захват параметров UTM (`utm_source`, `utm_medium`, `utm_campaign`, `utm_term`, `utm_content`).
2. **Раскрытие Dark Traffic (Прямых заходов)**:
   - Анализ посадочных страниц: если переход без Referrer произошел на внутреннюю продуктовою страницу, метрика маркирует его как `is_dark_traffic: true`.
   - Кэширование первичного источника в `sessionStorage` и `localStorage` под ключом `initial_ref`.
3. **Опрос при онбординге (Zero-Party Data)**:
   - Внедрен 8-й вопрос в калибровку ДНК («Как вы о нас узнали?»).
   - Сохранение `trafficData` и `discovery_source` напрямую в базу данных профиля пользователя в Supabase (`raw_onboarding_data`).
