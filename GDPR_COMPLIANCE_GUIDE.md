## 1. Публичные документы (Обязательный пакет)

На каждом проекте в футере и на странице авторизации должны быть активные ссылки на 3 документа:

1. **Privacy Policy (Политика конфиденциальности):**
   - Указывает Володельца данных (Юр. лицо / ФОП / Компания).
   - Перечисляет собираемые данные (Email, Telegram ID, медиафайлы, IP, куки).
   - Содержит права субъекта данных по ст. 8 Закона Украины № 2297-VI и GDPR (доступ, удаление, отзыв согласия).
2. **Terms of Service (Пользовательское соглашение / Оферта):**
   - Ограничение ответственности за сгенерированный ИИ контент (Disclaimers & Limitation of Liability).
   - Правила использования сервиса и запрет на нелегальный контент (Acceptable Use Policy).
   - Передача авторских прав на готовый результат пользователю.
3. **Refund Policy (Политика возврата средств):**
   - Условия 14-дневного окна возврата (при условии непотраченных кредитов/генераций).
   - Ссылка на Merchant of Record (Paddle / Tribute / Stripe).

## 2. Архитектура явного согласия (Active Consent)

Юридическая фраза *«Нажимая войти, вы соглашаетесь...»* без галочки **не является валидной** по GDPR и Закону № 2297-VI.

### Правило реализации:
1. Кнопки входа (Google, Telegram, Email) **заблокированы (`disabled`)**, пока пользователь не поставит галочку.
2. Текст возле галочки:
   > *"I consent to the processing of my personal data under the Law of Ukraine 'On Protection of Personal Data' (No. 2297-VI) and agree to the Privacy Policy."*
3. При входе в профиле сохраняется метаданное: `consent_given_at: ISO_TIMESTAMP`.

## 3. Самостоятельное удаление данных (GDPR Art. 17)

Пользователь должен иметь возможность **удалить свой аккаунт в один клик** в настройках профиля без необходимости писать в техподдержку.

### Техническая схема каскадного удаления:
При вызове API `/api/user/delete-account` выполняются следующие действия:
```typescript
// 1. Удаление пользовательских файлов и проектов
await db.from('projects').delete().eq('user_id', userId);
await db.from('renders').delete().eq('user_id', userId);
await db.from('transactions').delete().eq('user_id', userId);

// 2. Удаление профиля и аккаунта авторизации
await db.from('profiles').delete().eq('id', userId);
await db.auth.admin.deleteUser(userId);

// 3. Очистка сессионных куки
response.cookies.delete('auth-token');
```

## 4. Telegram-бот: Обработка удалений и блокировка (Blocklist)

Если пользователь просит удалить данные или отозвал согласие:
1. **Каскадно удалите** его `telegram_id` из базы данных.
2. **Добавьте его `telegram_id` в Blocklist (`blockedUsers.ts`)**, чтобы веб-приложение и бот не позволяли ему повторно зарегистрироваться или привязать бота.
3. **Проверка в вебхуке бота:**
   ```typescript
   if (isTelegramIdBlocked(user.id)) {
     return NextResponse.json({ ok: true }); // Игнорировать запросы заблокированного ID
   }
   ```

## 6. Безопасность и Merchant of Record (Paddle / Stripe)

1. **Merchant of Record (Paddle/Tribute):** Используйте MoR-сервисы. Они принимают на себя юридическую ответственность за сбор Sales Tax / НДС по всему миру и за безопасность PCI-DSS карт.
2. **Row Level Security (RLS):** Все таблицы в базе данных должны быть защищены правилом `auth.uid() = user_id`, чтобы исключить утечку данных между юзерами.
3. **Хранение секретов:** Никогда не передавайте API-ключи на клиентскую сторону. Все запросы к OpenAI, Anthropic, ElevenLabs выполняет только сервер.
